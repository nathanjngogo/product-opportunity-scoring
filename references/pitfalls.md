# 实战踩坑记录

真实做过 8 个版本的模型迭代，下面每一条都是实际失败后总结的。
按「坑 → 后果 → 根因 → 正确做法」组织。

---

## 一、模型方法论类

### 1. 秩变换做标准化

**现象**：用百分位排名标准化后，所有维度的熵值都是 0.9749（几乎相同），
熵权法给出的权重挤在 7.2%~7.9% 的窄带里，等价于等权。

**后果**：熵权、CRITIC 等所有基于"分布离散度"的赋权方法全部失效。

**根因**：秩变换会把任何分布压平成均匀分布。
均匀分布的标准差恒等、熵值恒等，差异信息被抹掉了。

**正确做法**：用 Winsorize(P1,P99) + signed-log(若|偏度|>2) + min-max。
保留分布形状才能让赋权方法工作。

---

### 2. 熵权法在异构指标集上不可靠

**现象**：熵权给「P8_毛利率」23.06% 的最高权重，
但该维度的变异系数 CV 只有 0.09（区分度评级"差"）。

**后果**：权重最大的维度恰恰是最没区分力的。

**根因**：熵权衡量的是"分布均匀度"而非"业务区分度"。
毛利率均值 68.7%、标准差 6.27，相对变异小，
但经 Winsorize + min-max 后在 0~1 区间分布很散，
熵值低 → 被判为"信息量大"。

**正确做法**：熵权/CRITIC 只适合同质指标集（都是连续、量级相近）。
本场景混合了连续值（毛利额）、计数（评价数）、比值（差评率）、
二值（有无视频），应放弃纯客观赋权。

---

### 3. 二值维度的熵权计算是病态的

**现象**：`P5a_无视频` 的取值只有 `100.0` 和 `0.0` 两种，
按 Shannon 熵公式算出来 E = 1.000000，权重归零。

**后果**：这个维度完全失效。

**根因**：Shannon 熵公式只统计非零值：

```python
p = [x / total for x in col if x > 0]   # 只剩 565 个 0.0018
k = 1.0 / math.log(len(p))
E = -k * sum(pi * math.log(pi) for pi in p)
# 所有 pi 相等 → sum = ln(565) → E = 1.0
```

**错误尝试**：改用 Bernoulli 熵 `H(p) = -p·ln(p) - (1-p)·ln(1-p)`。
结果反向爆炸——`P6_无A+` 拿到 59.13% 权重，
因为它的 p=0.108（232/2143），Bernoulli 熵很低，被判为"信息量极大"。

**正确做法**：二值变量不能进入熵权体系。
要么并入连续指标（如把"有无视频/有无A+ + 完整度"合成一个 Listing 质量分），
要么直接剔除。

---

### 4. IQR/中位 作为相对离散度

**现象**：`P4_Listing缺口` 的 IQR/中位 = 2.130，
而它的实际 CV(σ/μ) 只有 0.825。用前者算权重，该维度独占 47% 区分度份额。

**后果**：一个合成指标拿到 16.74% 权重，压过所有原始信号。

**根因**：IQR/中位 当分布严重右偏、中位数接近 0 时分母极小，比值爆炸。
`P4` 的中位数只有 0.067。

**正确做法**：用 σ/μ（均值做分母，不会爆）。
若仍担心离群值，先在计算前 Winsorize。

---

### 5. 特征值等权分配组权重

**现象**：PCA 得到 3 个成分，PC3 只含 `O_毛利额` 一个信号。
按"成分间等权"分配，该信号独得 33.33% 权重。

**后果**：单个信号的权重超过任何其他维度。

**根因**：成分等权假设每个成分同等重要，但 PC3 只解释 12.7% 方差。

**正确做法**：组权重 ∝ 特征值（即解释方差），
成分内按载荷平方分配。

---

### 6. PCA 会惩罚独立信号

**现象**：`G_月销量` 在 PC1 的载荷只有 0.262，份额 4.4%，
几乎被排除在模型之外。但月销量是最核心的需求信号。

**根因**：PCA 奖励"与其他变量共享方差"的变量。
`G` 与其他信号的 |ρ| 最大只有 0.233（高度独立），
所以载荷低。这是 PCA 的固有特性，不代表它无信息。

**错误补救**：我试过"独立信号单独给低保权重 1/(n+3)"，
结果 `BH/AJ/O` 也被判为独立（阈值 0.25 太宽），
四个信号各拿 14.29%，PCA 结构完全失效。

**正确做法**：不要用 PCA 做主权重。
若必须用，先明确"独立信号"的业务定义，而不是用相关性阈值。

## 二、数据处理类

### 7. 跨类目直接归一化

**现象**：吸尘器月销 8000、毛利额 $211；
手机壳月销 300、毛利额 $3。
放进同一个分布排序，手机壳全部垫底。

**后果**：模型实际上只在筛选"高客单类目"，而不是"好产品"。

**根因**：不同类目的量纲不可比。
实测方差分解显示，13% 左右的方差来自类目差异本身。

**正确做法**：类目内标准化（固定效应去均值）。
每个产品只与同类目内其他产品比较。

---

### 8. 补偿公式用加法

**现象**：
```python
ECAP = CAP + (100 - CAP) * TRD / 100
```
几乎所有类目的 ECAP 都落在 [90, 100]。

**后果**：区分度归零。

**根因**：TRD 最低也有 12 分（因为百分位排名，最低不是 0），
所以 `(100-CAP)*TRD/100` 这一项总能加不少分。

**正确做法**：加权几何 `CAP^(1-θ) × TRD^θ`，θ 随容量缺口变化。

---

### 9. 趋势表行号不偏移

**现象**：趋势表产品表行号不一致，产品表数据从 r5 开始，
趋势表从 r2 开始。直接用同一个行号取数据，全部错位。

**后果**：类目趋势算的是别人家的数据。

**正确做法**：
```python
def trend_of(row):
    return trend_data.get(row - 3, {})
```
**必须验证**：抽查前 50 条，确认非空。

---

### 10. `AT` 列取到英文行

**现象**：`AT` 是多行中英对照：
```
Tools & Home Improvement -> Appliances -> Refrigerator Filters
工具和家庭改善 -> 家用电器 -> 冰箱水过滤器
```
直接 `split("\n")[0]` 取到英文行。

**后果**：如果后续逻辑依赖中文关键词，全部失效。

**正确做法**：
```python
for line in (at or "").split("\n"):
    if any("\u4e00" <= ch <= "\u9fff" for ch in line):
        return [s.strip() for s in line.split("->") if s.strip()]
```

---

### 11. 过滤条件写反

**现象**：
```python
keep_rows = {x["row"] for x in cls["records"] if x["delete"]}
```
少了 `not`，读进来的是**已删除**的产品。

**后果**：样本 2857 而不是 2143，全部结论错误。

**正确做法**：加断言。
```python
assert N == len(keep_rows), f"{N} vs {len(keep_rows)}"
```

---

### 12. 原地修改导致后续计算失败

**现象**：
```python
np.fill_diagonal(Rm, 0)      # 算 Bartlett 时清空对角线
evals = np.linalg.eigvalsh(Rm)  # 后面又用 Rm 做特征分解
# 得到负特征值 [-0.721, -0.740]
```

**后果**：PCA 结果完全错乱，平行分析判定"保留 0 个成分"。

**正确做法**：需要修改时用副本。
```python
Rm_off = Rm.copy()
np.fill_diagonal(Rm_off, 0)
```

---

### 13. None 值未过滤导致崩溃

**现象**：
```python
mean([x["aj"] for x in group])   # TypeError: can't convert NoneType
```

**后果**：脚本中断，且报错位置不在数据源头，排查困难。

**正确做法**：所有聚合前统一过滤。
```python
vals = [x["aj"] for x in group if x["aj"] is not None]
if not vals:
    continue
```

## 三、写作类

### 14. Excel 列移位时把 A 列也移了

**现象**：在 URL 列后插入新列时，把所有列（包括 A）都右移一位。

**后果**：A 列变空，序号跑到 B 列，整表错位。

**正确做法**：只移 `col_index > split_index` 的列。
```python
def shift_col_after(letters, split_idx=6, delta=1):
    i = col_to_idx(letters)
    return idx_to_col(i + delta) if i > split_idx else letters
```

### 15. 星级写成文本

**现象**：
```python
cell = f'<c r="{col}{rn}" t="inlineStr"><is><t>{stars}</t></is></c>'
```
Excel 里是文本 `"3"` 而不是数字 `3`。

**后果**：无法排序、无法筛选、无法做条件格式。

**正确做法**：写数值单元格。
```python
cell = f'<c r="{col}{rn}" t="n"><v>{stars}</v></c>'
```

### 16. PowerShell 写文件带 BOM

**现象**：
```powershell
Set-Content $path -Value $json -Encoding UTF8
```
写入的文件开头有 `EF BB BF`。

**后果**：Python `json.load()` 报 `Unexpected UTF-8 BOM`。

**正确做法**：
```python
open(path, encoding="utf-8-sig")
# 或写文件时
open(path, "w", encoding="utf-8", newline="")
```

### 17. 权重之和不归一

**现象**：业务先验手写权重，加起来是 0.9 不是 1.0。

**后果**：断言失败，或（若不检查）分数整体偏低。

**正确做法**：归一化并断言。
```python
_s = sum(PRIOR.values())
PRIOR = {k: v / _s for k, v in PRIOR.items()}
assert abs(sum(PRIOR.values()) - 1.0) < 1e-9
```

### 18. 类目路径缺失的记录被塞进同一组

**现象**（日本站 5000 条验证时发现）：
87 条产品类目路径为 `--`（1.7%），全部归入 `(无)` 组。
该组月销额中位 ¥1706 万（≈ $11 万），体量大 → 拿到较高类目分
→ **8 个产品误进 5 星**，其中 3 个是任天堂 Switch 游戏卡带。

**后果**：类目级指标（容量/CR/新品）完全失真，因为该组横跨
游戏、母婴、日用品等完全不同的品类。

**根因**：`_assign()` 里 `segs` 为空时统一写 `"(无)"`，
把「无法判定类目」当成「一个真实类目」处理。

**正确做法**：三级兜底 + 中性处理

```
L1 类目路径 → 二级类目
L2 缺失 → 大类名称列（AL）
L3 再缺失 → 小类名称列（AP），剥掉 "#1," 前缀
L4 全缺 → cat_missing: 全局标准化，跳过类目级计算，类目分取中位
```

**验证**：补丁后 L2 救回 81 条并归入正确大类（ゲーム/ビューティー等），
L4 仅剩 6 条走中性，**缺失类目进 5 星从 8 个降到 0 个**。
美站 2143 条回归测试结果完全不变（CV 0.627 / 5星 215）。

**注意**：不要用「小类名称」优先于「大类名称」。
小类名常带排名前缀，且粒度过细（可能一个产品独占一类），
大类名本身就是可信的分组键。

## 四、跨市场验证类

### 19. 同一套类目规则不能跨语言复用

**现象**：把美站的中文类目规则（`classify.py`）直接套到日本站，
命中率为 0——日本站类目全是日文（`ドラッグストア`、`ビューティー`）。

**更隐蔽的问题**：即使强行翻译关键词，类目结构也不同：

| 品类 | 美站位置 | 日本站位置 |
|---|---|---|
| 保健品 | 健康与家庭/维生素矿物质 | **ビューティー/栄養補助食品**（在美妆树下） |
| 药品 | 健康与家庭/保健产品 | ドラッグストア/医薬品・指定医薬部外品 |
| 相机 | 独立一级类目 | 合并进 **家電＆カメラ** |
| 手机周边 | 手机和配件 | 家電＆カメラ/アクセサリ・サプライ/携帯電話～ |

**后果**：只翻译词表会让保健品漏删（在日本站它在美妆树下）。

**正确做法**：每个市场先跑「类目分布探查」，看一级/二级/三级类目构成，
再写该市场的独立词表。不要复用别的市场的规则文件。

### 20. 宠物类目的层级结构与其他类目不同

**现象**：写宠物食品规则时检查 `sub`（第二层），但日文结构是
`ペット用品->犬->ドッグフード`——第二层是**宠物类型**，
第三层才是**品类型**。规则不生效。

**根因**：多数类目是 `大类->子类->叶子`，宠物类是
`大类->宠物种类->品类型`，语义层级不同。

**正确做法**：宠物类判定同时检查 `sub` 和 `leaf`，
并用名称关键词兜底（`フード`/`おやつ`/`餌`）。

**验证**：修复前 121 条宠物用品里 64 条猫狗粮全保留；
修复后正确识别为「食品」。

### 21. 游戏软件与虚拟商品容易被当成普通商品

**现象**（日本站）：
- 50 条 Switch 游戏卡带（`ゲーム` 类目）被保留
- 3 条预付卡/礼品卡（任天堂/Roblox/PS 充值券）被归入「低客单价」

**根因**：
- 游戏软件类目名（`ゲーム`）不含「食品」「美妆」等提示词
- 虚拟商品有「价格」字段（面值），能通过价格筛选

**正确做法**：
- 游戏软件：类目为 `ゲーム` 且名称含 `-Switch`/`PS5 用` 等，但排除
  `アクセサリ`/`フィルム`/`ケース`（配件是实体的）
- 虚拟商品：名称含 `ギフトカード`/`プリペイド`/`ゲームコード`/`Robux`
  等，**放在判定链最前面**（优先于价格筛选）

### 22. 消毒/除菌类容易漏在日化之外

**现象**：`ドラッグストア/日用品` 下除了纸品垃圾袋，还混着
洗濯・仕上げ剤（洗衣液）、洗浄・クリーナー剤（清洁剂）、
消臭・芳香剤（除臭芳香）、防虫剤（防虫剂）。

**后果**：只按「日化 = 纸品 + 垃圾袋」的规则，331 条化学品会漏掉。

**正确做法**：把「化工」和「日化」分开定义，两者都在
`ドラッグストア/日用品` 下，靠三级叶子区分：
- 化工：洗濯/洗浄/除菌/消臭/芳香/防虫/防カビ/除湿/油処理
- 日化：トイレットペーパー/ティッシュ/ごみ袋/ウェットティッシュ/おむつ

### 23. 多义词必须配排除表（拉丁语系特有）

**现象**（意大利站 5000 条）：
用 `ricarica` 判定虚拟商品，误删 **139 条**，其中 134 条是这个词造成的：

| 误判样例 | 实际是什么 |
|---|---|
| `Batterie AAA NiMH Performance ricarica` | 充电电池 |
| `INIU Power Bank 20000mAh Ricarica Rapida` | 快充充电宝 |
| `Cavo USB Ricarica Rapida` | 充电线 |
| `Sapone Liquido Ricarica Universale` | 洗衣液补充装 |
| `Ariasana Aero 360° Ricarica` | 芳香剂补充装 |

**根因**：`ricarica` 在意大利语至少三义——充电（电池/线）、补充装（洗剂/芳香剂）、充值（电话卡）。
单靠「包含该词」判定必然误伤。

**正确做法**：双表机制

```python
VIRTUAL_KW = ["carta regalo", "gift card", "codice digitale",
              "Robux", "V-Bucks", "abbonamento a", ...]
VIRTUAL_EXCLUDE = ["ricarica", "ricaricabile", "batteria",
                   "power bank", "cavo", "caricatore"]
# 命中 KW 且未命中 EXCLUDE 才判定
```

**同时要**：优先用专有搭配而不是单词（`carta regalo` 而非 `regalo`）。

**效果**：139 → 4 条，剩下全是真虚拟商品（PS Store / Xbox / Robux / eShop 卡）。

**推广**：西语 `recarga`、法语 `recharge`、德语 `Aufladen` 都是同一个坑。

### 24. 营养成分名不能用来判定保健品

**现象**（意大利站）：`vitamin` / `vitamina` 做保健品名称兜底，误判 **37 条化妆品**：

| 误判样例 | 实际是什么 |
|---|---|
| `medicube Capsule Cream with Deep Vitamin C` | 面霜 |
| `Garnier Siero Viso Vitamina C Anti-Macchie` | 精华液 |
| `L'Oréal Paris Crema Viso Giorno Revitalift` | 日霜 |

**根因**：营养成分名（vitamin / vitamina / collagen / 胶原蛋白）在
**化妆品和保健品里都会出现**，不构成品类判据。

**正确做法**：名称兜底只用「品类专有词」

```python
# ❌ 错：营养成分名
SUPP_NAME_KW = ["vitamin", "vitamina", "collagen"]

# ✅ 对：品类专有词
SUPP_NAME_KW = ["integratore", "integratore alimentare",
                "supplemento", "proteine in polvere", "omega 3"]
```

**主判据仍应是类目**（`Vitamine, minerali e integratori`），名称只是兜底。

**同理**：日语 `ビタミン`、西语 `vitamina`、法语 `vitamine` 都适用。

### 25. 「大类组」不能整组判定，必须按叶子分流

**现象**（意大利站）：
`Salute e cura della persona > Pulizia e cura della casa` 整组划为化工，
但该组同时含纸品，**50+ 条卫生纸被误判为化工**：

| 实际内容 | 应归类 |
|---|---|
| `Carta igienica`（卫生纸）、`Rotoli`（卷纸） | 日化 |
| `Tovaglioli e fazzoletti`（餐巾纸巾） | 日化 |
| `Detersivo`（洗衣液）、`Candeggina`（漂白剂） | 化工 |

**根因**：亚马逊的类目组常把「清洁用品」作为一个大类，
但里面既有化学品（液体）也有纸品（固体耗材）。整组判定必然误伤一半。

**正确做法**：建「组内例外表」，优先判定

```python
# 先判例外
CHEM_TO_DAILY = {"Carta igienica", "Rotoli di carta igienica",
                 "Prodotti di carta", "Tovaglioli e fazzoletti",
                 "Panni e spugne", "Salviette umidificate"}

if leaf in CHEM_TO_DAILY:
    → 日化
elif leaf in CHEM_LEAVES:
    → 化工
```

**判据**：**看叶子（leaf）不看组（sub）**。
只要一个 sub 下混着两种品类，就必须按 leaf 分流。

**自查方法**：跑完分类后统计每个删除类别的三级叶子分布，
若某类别下出现明显不该有的叶子 → 说明整组判定误伤。

## 五、方法选择类（最重要的教训）

### 26. 不要假设数据支持自定义权重

**现象**：连续 6 个版本都在试图"算出"权重
（熵权、CRITIC、PCA、组合赋权、先验融合、限幅调整），
每次都被自己的检验推翻。

**最终结论**：先算 **KMO**。

- KMO < 0.6 → 数据不支持因子分析，**等权**
- KMO 0.6~0.8 → 可考虑 PCA 载荷
- KMO > 0.8 → PCA/因子分析可用

实测 KMO = 0.48，直接等权。省掉后面所有弯路。

**依据**：OECD/JRC《Constructing Composite Indicators》手册。
维度相关性低时，任何赋权都缺乏依据。

---

### 27. 每个"改进"都要被检验否决一次

**做法**：每次改模型，先问"这个改动应该让哪个指标变好"，
然后用数据验证。如果没变好，改回去。

**实例**：
- 改用几何平均 → 区分度 CV 应从 0.19 提升 → 实测 0.599 ✓
- 加类目维度 → 单调性应保持 → 实测保持 ✓
- 补偿公式用加法 → 区间应拓宽 → 实测坍缩 ✗ → 改几何
